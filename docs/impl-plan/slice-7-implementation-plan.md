# Slice 7 implementation plan

A candidate writes code and draws during one active interview. The assigned panelist follows committed changes on a second device and completes the existing assessment after closure. Success requires a Windows candidate, a Mac panelist, restored work after reconnect, and immediate denial of artifact reads by a closed candidate session. Use synthetic interviews for verification. [Slice 7 requirements](../core/requirements-roadmap.md#7-add-the-live-editor-and-whiteboard) · [Interview workspace](../core/product-plan.md#interview-workspace) · [Saving and reconnecting](../core/architecture.md#interview-and-job-data-flows)

## 1. Establish persistence, access and closure together

**Storage.** Add an additive Drizzle migration and shared workspace schemas. Key each head by round UUID and kind, `code` or `board`. A missing head means sequence zero and null revision ID. Return the JavaScript Hello World starter for an active round with no saved code and an empty board. Preserve any saved source, including a deliberately empty file. This also serves existing active attempts upgraded mid-round. A fresh L2 or rebooking gets different heads. Reads have no creation side effects. [Interview schema](../../apps/server/src/interviews/schema.ts) · [Migration history](../../apps/server/drizzle/meta/_journal.json) · [Shared contracts](../../packages/contracts/src/index.ts)

- Append an immutable row with revision UUID, round ID, kind, positive sequence, schema version, validated payload, author session ID and server-assigned save time. Enforce unique round/kind/sequence and a composite foreign key from each head to its own revision. Order by sequence. Keep a later save or undo as a new revision. Leave the round lifecycle revision and assessment draft revision independent of typing.
- Store complete snapshots in PostgreSQL. Keep committed revisions across closure, correction and rebooking. Slice 10 can later reference the immutable UUID with a same-attempt and kind constraint, protect references from a draft and every submitted assessment version, and authorize lookup via the citing assessment. Slice 7 exposes only authorized heads. It needs neither a public history endpoint nor a citation picker.
- Proposed candidate HTTP routes beneath `/api/interviews/rounds/:id` are `GET /workspace` for the two head descriptors and an identity binding, `GET /workspace/:kind` for one current snapshot, and `POST /workspace/:kind` for a complete candidate save. Mirror the reads under `/api/staff/my-interviews/:id`. Keep the HR scheduling queue named `/interviews/workspace` separate. [Candidate routes and cookie path](../../apps/server/src/interviews/candidate-routes.ts) · [Staff interview routes](../../apps/server/src/interviews/staff-routes.ts)
- Reuse the round/session/invitation checks from `candidateRound`. Each candidate artifact operation requires the current unrevoked invitation and session, that session's own profile confirmation, and active state. Read authorization and the artifact from the same database snapshot. Serialize saves and closes on the round row. An already admitted candidate can reconnect in overtime. Fresh verification within the entry window supersedes the preceding session and requires fresh profile confirmation. [Candidate identity](../../apps/server/src/interviews/admission.ts)
- For staff, carry the authenticated Better Auth session ID and user ID from middleware into the workspace module. Read session expiry, verified approved-domain identity, effective panelist role, exact assignment, round state and snapshot together from one database statement. Evaluate the approved-domain rule using the verified email from that same read. On writes, take the staff row lock used by role changes, lock the authenticated session row against deletion, then lock the round and recheck authorization and expiry before applying the command. Preserve staff-before-round ordering and validate the ordering with existing role, password reset and closure operations. [Staff middleware](../../apps/server/src/staff/routes.ts) · [Staff identity](../../apps/server/src/staff/roles.ts) · [Staff session schema](../../apps/server/src/staff/auth-schema.ts)
- Bind a mounted editor, its requests and its socket to the attempt and authenticated session that opened it. The first descriptor request returns a server-derived opaque comparison value and head metadata. Send the binding in a dedicated same-origin header on subsequent reads, saves and candidate close. The server always authenticates the cookie before comparing the binding. A second verification can replace the cookie for every tab in that browser. On mismatch, clear the old mount and its queue, then require fresh initialization. Reject late fetches and acknowledgments from an older mount.
- Each save includes a stable command UUID, expected base sequence, binding, and validated payload. Lock the round, check access, then check the session-scoped receipt using a deterministic fingerprint of the round, kind, base and canonical payload. An exact retry returns its original committed UUID and sequence even after the head advances. A changed command with the same key fails. Reject a mismatched base with a scoped conflict. Otherwise insert the revision, advance its head, record the receipt and signal the change in one transaction. Return the acknowledgment only after commit. Use the existing candidate lock order for candidate commands and preserve the staff lifecycle lock order. [Receipt and revocation helpers](../../apps/server/src/interviews/store.ts)
- Candidate close uses the existing idempotent end command. On opening the dialog freeze edits and flush pending changes to **both** tools, including the hidden tab. Resolve lost save responses with their original keys. Enable final confirmation only after all saves are acknowledged. Send the displayed round revision, the expected pair of committed head IDs, identity binding and stable close command ID. Under the round lock recheck all three revisions before calling `closeRound`. A competing tab's save triggers a conflict and requires review and fresh confirmation. A failed flush keeps the interview open with a retry or return-to-editing action. Cancelling the dialog resumes editing.
- Require the expected heads and binding for every new candidate close, including two empty heads. Direct older clients to refresh. Retry a lost close response with the exact original command. A matching close receipt, including a receipt written before the upgrade, may return generic completion to the same revoked candidate session. Other operations require current access. If staff closes first, reject outstanding work. If a save commits first, retain that head even when its HTTP acknowledgment was lost. A remote close uses the database heads and completes immediately even when an editor is offline.
- Publish an ID-only invalidation in the transaction that changes access for `closeRound`, admission revocation, scheduled reassignment, replacement by a newly verified candidate session, active withdrawal, L1 pass reversal and staff role changes. Recheck staff sessions on delivery and on the idle heartbeat so sign-out, expiry and password reset also remove access, including idle connections. A rollback emits nothing. The database decision governs every new request and delivery. Install and test these rules before exposing an editor. [Close and reassignment](../../apps/server/src/interviews/scheduling.ts) · [Correction cancellation](../../apps/server/src/interviews/assessments.ts) · [Staff session revocation](../../apps/server/src/staff/auth.ts) · [Existing end dialog](../../apps/web/src/interviews/end-dialog.tsx)

| Attempt state | Candidate | Currently assigned panelist with an eligible session |
| --- | --- | --- |
| Scheduled, including the waiting room | Admission, profile and presence only | Booking details, start when eligible, and the existing L2 handoff |
| Active | Read and save both tools, follow live events, confirm closure | Read both tools, follow live events, record a private concern in virtual mode, and use the existing notes and assessment |
| Awaiting feedback | Ended screen | Load final committed heads over HTTP, read own concerns and use the existing notes and assessment |
| Feedback submitted | Ended screen | Consult final heads and own concerns for that attempt, and review or correct feedback under the existing rules |
| Cancelled, withdrawn or no-show | Unavailable screen | Read retained final heads and own concerns for a previously started attempt if still assigned and eligible. An unstarted attempt has no workspace. |

HR, directors and other panelists follow their existing workflows and receive no raw artifacts or private concerns in any state. Candidate content is cleared on revocation. On an active-to-awaiting-feedback transition, the assigned panelist's socket closes and the page revalidates access and fetches the committed heads over HTTP. Show those heads in the feedback view even if the last live event never arrived.

## 2. Deliver one live code interview

1. Add attempt-scoped `/live` upgrades under each authorized HTTP prefix so the browser sends the existing round-path candidate cookie. Use `ws` 8.23.0 and the pinned Node adapter's `upgradeWebSocket` with `serve({ websocket: { server } })` on the existing listener. Restrict upgrades to those routes, validate the trusted browser Origin explicitly, canonicalize the round ID and authenticate the route's own cookie. Maintain independent candidate and staff authentication. Forward upgrades on the development `/api` proxy using `STUDIO_API_ORIGIN` and preserve the original browser Origin. Release sockets, timers and the dedicated database listener on shutdown. [Server startup](../../apps/server/src/main.ts) · [Application routing](../../apps/server/src/app.ts) · [Development proxy](../../apps/web/vite.config.ts) · [Connection pool](../../apps/server/src/database.ts)
2. Once the upgrade authenticates, accept an initial bind message containing the opaque session comparison value. Recheck the current session and compare it with the authenticated connection before subscribing or sending events. Apply a short bind deadline and include pending connections in the socket limits. Use small, typed ready, head-changed and access-ended events. A change identifies kind and sequence. Fetch the content through the corresponding authorized HTTP route. Keep credentials, workspace content and observations out of socket frames, URLs and logs. Use a dedicated PostgreSQL notification listener per app process. Subscribe before announcing ready, then reconcile heads on ready and periodically while active. Recheck each recipient's original session, role, attempt and state before notifying. Reauthorize idle sockets on a bounded heartbeat and promptly disconnect sockets affected by a committed access change. Listener loss closes subscriptions and triggers a fresh authorized handshake.
3. Bound concurrent connections per session, total sockets, heartbeat deadlines, incoming frame size and queued outgoing bytes. Pilot starting values are four sockets per identity, 128 per app, 1 KiB control frames, a 15-second heartbeat and disconnect after two missed replies. Reject binary and unexpected application frames. Coalesce head notices per kind, disconnect slow consumers at a proposed 32 KiB send backlog, and let them reconcile on reconnect. Cap concurrent writes and save frequency with retryable throttling. Tune these limits using the two-device rehearsal and keep the limits enforceable on the server. Keep operational logs to IDs, sizes, timings and error codes.
4. Lazy-load CodeMirror 6 into the active candidate and assigned panelist round pages. Use one visible source buffer and a language selector for JavaScript, Java and Python. On first use of a language, show its Hello World starter. Save each inactive language draft with the active source and language in the same revision. Switching back restores the saved text, including indentation, whitespace, Unicode and deliberately empty drafts, without mixing undo histories. Store at most 64 KiB of valid UTF-8 source per language. Text input for execution, runner dispatch, results and replay belong to Slice 8. Keep panelist editing disabled in the widget and at the server. Verify exact packages, language extensions, read-only behavior and production bundling against the pinned release during implementation. [Candidate page](../../apps/web/src/interviews/candidate-pages.tsx) · [Assigned round page](../../apps/web/src/interviews/panelist-pages.tsx) · [Web dependencies](../../apps/web/package.json)
5. Keep one queue per artifact above the tool tabs. Debounce edits for roughly 750 ms and flush at least every five seconds of continuous valid editing, subject to in-flight saves and retry backoff. Serialize writes per kind and coalesce later local edits behind the in-flight snapshot. Track the latest observed server head separately from the base of the local draft. A matching acknowledgment advances the base for edits made on top of the acknowledged snapshot. A fetched remote head only replaces the buffer and base when the editor is clean. Ignore duplicate or delayed events, prevent older HTTP responses overwriting newer heads, and skip saves for hydration and unchanged content. Keep round polling and presence independent of tool loading.
6. Show **Saving**, **Saved**, **Reconnecting**, **Unsaved changes** and an actionable conflict or validation message. Reconcile on connect, visibility return, focus and a bounded fallback poll. Compare lightweight head descriptors before fetching content. On a network error, timeout, throttling or server error keep the mounted draft and resolve the uncertain command by replaying the same key and payload with capped backoff. If the actual head has advanced beyond that command's acknowledged revision while local edits are pending, pause that tool and keep the dirty base. Let the user load and inspect the current snapshot and manually apply changes they want to keep. A socket outage permits authorized HTTP saves and polling. Refresh restores committed content. Warn before leaving with unsaved edits and keep drafts in memory only. A terminal denial clears content, cancels requests and closes the connection. On back/forward cache restore, hide old content until authorization succeeds. [Request, polling and denial handling](../../apps/web/src/interviews/api.ts)

## 3. Add the whiteboard and private observations

**Board.** Lazy-load Excalidraw 0.18.1 in its own panel. Persist a versioned scene using an explicit allowlist tested against the pinned package. Support ordered freehand strokes, rectangle, ellipse, diamond, line, arrow and plain text. Support movement, selection, erase and undo in the active editing session. Restore the same geometry, style, stacking and text on refresh. Applying a complete remote scene removes elements absent from that snapshot. Undo after a save persists the resulting scene through the normal save path. A refreshed page starts a new undo history. Initial load and read-only updates never echo as candidate saves. A failed board chunk offers retry and leaves code, notes and closure available.

- Keep IDs, order, finite coordinates, supported styles and bounded freehand point and pressure arrays. If supporting bound text or arrows, preserve and validate their in-scene references. Strip transient selection, collaborators, viewport, undo stack and tombstones from the persisted representation. Test round-trip fidelity with the chosen tools before committing the schema. Deny unknown types, unexpected fields, external links, embeds, images, imported files, data URLs and binary assets at both UI ingress and the server. Serve required static fonts, styles and tool assets from the application origin. Disable vendor collaboration, libraries, share/export actions and remote asset loading. Verify the packaged assets and network requests in the production image. [Planned tool choices](../core/architecture.md#technology-choices) · [Production image](../../Dockerfile)
- Proposed pilot bounds are 512 KiB per serialized scene, 500 elements, 20,000 total points, 4,000 per stroke, 4,000 Unicode characters per text element and absolute coordinate magnitudes up to one million. Bound strings, ID lengths, nesting and reference counts. Count actual UTF-8 wire bytes before JSON parsing, including chunked requests. Use a JSON object for the scene payload. Allow 1.25 MiB for a code request to fit three language drafts with JSON escaping and 544 KiB for a board request. Keep admission, end and presence at their current 2 KiB ceiling and apply larger limits only on the save routes. Exercise the exact limit and one byte over with escaped and multibyte input. [Candidate body limit](../../apps/server/src/interviews/candidate-routes.ts) · [JSON validation](../../apps/server/src/interviews/http.ts)
- Validate code, all persisted scene strings and concern text as well-formed Unicode and reject U+0000. Reuse the existing assessment text validation rule where possible. Keep invalid content editable and show the affected tool and field with a workspace-specific message for validation and 413 responses. If the hidden tool blocks candidate closure, link to it and let the candidate fix the draft or explicitly discard that tool's unsaved changes and reload its last committed head. Recheck both tools before confirming closure. [Existing text validation](../../packages/contracts/src/assessments.ts) · [Interview error messages](../../apps/web/src/interviews/api.ts)
- Give Code and Whiteboard keyboard-operable tabs, named toolbars and read-only labels. Keep focus on the user's control across saves and peer updates. Offer one Full screen toggle in the shared toolbar. Keep the tools mounted while expanded, support switching tabs with the keyboard, and return focus to the toggle on exit. Provide visible focus, tool shortcut help and a keyboard escape from editor/canvas. Offer keyboard text entry, undo, delete and a readable scene summary with text elements for the panelist. Announce meaningful status changes without reading every keystroke. Test screen-reader navigation, zoom, a narrow viewport, large local drafts, conflict recovery and focus return after ending.

**Virtual concern.** Add an assigned-panelist-only form near the existing private notes, mounted on the round page independently of assessment criteria and draft initialization. Require an observation and its context (for example the question being discussed), each with an initial limit of 1–1,000 characters. Append a private attempt record with opaque ID, author staff ID and server timestamp. Limit new entries to active virtual rounds, start with a cap of 50 per attempt, and use a stable command receipt for retry. After closure an exact retry can confirm the prior save to its still-authorized author. The same author can identify the saved entry in readback even after a response is lost. Enforce role, session, assignment, mode and lifecycle through a private endpoint under the assigned round path. Save concerns independently so unsaved scorecard inputs and the assessment draft revision survive. In person use the existing private notes field. Keep concern payloads out of shared snapshots, WebSocket events, candidate responses, HR and Director scorecards, L1 handoffs, logs and automatic decisions.
